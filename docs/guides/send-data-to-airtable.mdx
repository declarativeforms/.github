---
title: Send data to Airtable
description: How to create Airtable records from form submissions
---

An `airtable` connection creates a new record in an Airtable base whenever a form is completed.

## Prerequisites

You must first connect your Airtable account via OAuth:

1. Go to [app.declarativeforms.com/connections](https://app.declarativeforms.com/connections)
2. Click **Connect Airtable**
3. Authorize the OAuth app with access to your Airtable bases
4. Copy the `connection_id` shown after authorization

## Configuration

```yaml
connections:
  - type: airtable
    connection_id: your-airtable-connection-id
    base_id: appXXXXXXXXXXXXXX
    table_id_or_name: Submissions
```

| Property | Description |
|----------|-------------|
| `connection_id` | The ID from the connections page after OAuth |
| `base_id` | Your Airtable base ID (starts with `app`) |
| `table_id_or_name` | The table name or table ID (starts with `tbl`) |

## Field mapping

The entire `submission.data` object is sent to Airtable as the `fields` object. This means **your form field IDs must match your Airtable column names exactly**.

For example, if your form has:

```yaml
fields:
  - id: name
    type: short_text
    label: Full name
  - id: email
    type: email
    label: Email address
  - id: message
    type: long_text
    label: Message
```

Your Airtable table must have columns named `name`, `email`, and `message`.

## Finding your base ID and table ID

**Base ID**: Open your base in Airtable, then go to **Help > API documentation**. The base ID appears in the URL and the docs (e.g., `appXXXXXXXXXXXXXX`).

**Table name**: Use the exact name shown in the Airtable tab (case-sensitive). Alternatively, use the table ID from the API docs (starts with `tbl`).

## Timing

Airtable connections fire **only when the submission status is `completed`**—when the user submits the final section. They do not fire for partial saves.

## Full example

```yaml
version: 1
title: Lead Capture

sections:
  - id: lead
    title: Tell us about yourself
    fields:
      - id: name
        type: short_text
        label: Full name
        validators:
          - required
      - id: email
        type: email
        label: Work email
        validators:
          - required
      - id: company
        type: short_text
        label: Company
      - id: use_case
        type: long_text
        label: What are you looking to build?
    next: done

connections:
  - type: airtable
    connection_id: abc123
    base_id: appXXXXXXXXXXXXXX
    table_id_or_name: Leads

  - type: email
    to: "{{data.email}}"
    subject: "Thanks for your interest, {{data.name}}!"
    body: "<p>We'll be in touch shortly.</p>"
```

## Notes

- If the `connection_id` is invalid or the OAuth token has expired, the Airtable connection is silently skipped
- OTP token fields (e.g., `email__otp_token`) will be included in the `fields` object—create a matching column in Airtable if you want to capture them, or ignore them
- Airtable field types must be compatible with the submitted values (e.g., a Number field in Airtable expects a number, not a string)
