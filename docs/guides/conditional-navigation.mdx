---
title: Branch on Answers
description: Route applicants to different sections based on what they select.
---

Not every applicant needs every section. Studio applicants don't need employment verification — it's irrelevant for a lower-cost unit. This guide changes the property section's `next` to branch based on the selected unit type, and adds an employment section for non-studio applicants.

---

## What to add

Replace the flat `next: done` on the property section with a conditional `next` block, and add a new `employment` section.

Change the property section's `next`:

```yaml
    next:
      - when: "data.unit_type === 'studio'"
        go: done
      - else: employment
```

Add the `employment` section after `property`:

```yaml
  - id: employment
    title: Employment
    fields:
      - id: employer
        type: short_text
        label: Employer name
        validators:
          - required
      - id: monthly_income
        type: number
        label: Monthly income (USD)
        validators:
          - required
    next: done
```

---

## How conditional navigation works

When `next` is a list of rules, they are evaluated top-to-bottom. The first rule whose condition is satisfied determines where the form goes next.

**`when`** — a JavaScript expression evaluated against `data`. Same syntax as `visible_when`.

**`go`** — the section `id` to navigate to if `when` is true. Use `done` to complete the submission.

**`else`** — the fallback destination if no `when` condition matched. Functions like a final `else` branch.

Rules are evaluated at submission time, using the values from the section just submitted.

## Complete `rental.yaml`

```yaml
version: 1
title: Rental Application

sections:
  - id: personal
    title: Personal details
    fields:
      - id: full_name
        type: short_text
        label: Full name
        validators:
          - required
      - id: email
        type: email
        label: Email address
        validators:
          - required
      - id: move_in_date
        type: date
        label: Desired move-in date
        validators:
          - required
    next: property

  - id: property
    title: Property details
    fields:
      - id: unit_type
        type: single_select
        label: Unit type
        options:
          - value: studio
            label: Studio
          - value: 1br
            label: 1 bedroom
          - value: 2br
            label: 2 bedrooms
          - value: 3br
            label: 3+ bedrooms
        validators:
          - required
      - id: has_pets
        type: single_select
        label: Do you have pets?
        options:
          - value: "yes"
            label: "Yes"
          - value: "no"
            label: "No"
        validators:
          - required
      - id: pet_details
        type: short_text
        label: Pet details
        placeholder: Breed, size, and number of pets
        visible_when: "data.has_pets === 'yes'"
    next:
      - when: "data.unit_type === 'studio'"
        go: done
      - else: employment

  - id: employment
    title: Employment
    fields:
      - id: employer
        type: short_text
        label: Employer name
        validators:
          - required
      - id: monthly_income
        type: number
        label: Monthly income (USD)
        validators:
          - required
    next: done
```
