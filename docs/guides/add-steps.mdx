---
title: Add Multiple Steps
description: Split your form across screens with sections.
---

The quickstart form puts everything in a single section. When a form grows beyond a few fields, splitting it into sections keeps each screen focused and reduces abandonment. This guide adds a second section to `rental.yaml`.

---

## What to add

Replace the single `main` section with two sections: `personal` and `property`. Each section has its own `next` value pointing to the next step.

```yaml
sections:
  - id: personal
    title: Personal details
    fields:
      - id: full_name
        type: short_text
        label: Full name
        validators:
          - required
      - id: email
        type: email
        label: Email address
        validators:
          - required
      - id: move_in_date
        type: date
        label: Desired move-in date
        validators:
          - required
    next: property

  - id: property
    title: Property details
    fields:
      - id: unit_type
        type: single_select
        label: Unit type
        options:
          - value: studio
            label: Studio
          - value: 1br
            label: 1 bedroom
          - value: 2br
            label: 2 bedrooms
          - value: 3br
            label: 3+ bedrooms
        validators:
          - required
    next: done
```

---

## Section properties

| Property | Type | Description |
|----------|------|-------------|
| `id` | string | Unique identifier for the section. Used in `next` values and in the URL (`?step=<id>`). Required. |
| `title` | string or locale map | Displayed as the section heading. |
| `description` | string or locale map | Optional subtitle displayed below the heading. |
| `fields` | array | The fields to show on this screen. |
| `next` | string or NavigationRule[] | Where the form goes after this section is submitted. Required. |

Sections are presented in the order they are navigated, not the order they appear in the file. The form always starts with the first section in the list.

---

## `next` values

`next` controls navigation after a section is submitted. It accepts four forms:

**Section ID** — advance to a specific section:
```yaml
next: property
```

**`"done"`** — complete the submission and show the completion screen:
```yaml
next: done
```

**URL** — redirect to an external URL after submission:
```yaml
next: https://example.com/thank-you
```

**Conditional rules (`NavigationRule[]`)** — evaluate conditions in order; the first matching rule wins. Each rule has a `when` expression and a `go` destination:

```yaml
next:
  - when: "fields.unit_type === 'studio'"
    go: studio_details
  - when: "fields.unit_type === '1br'"
    go: one_bed_details
  - go: done
```

The last rule may omit `when` to serve as a default. `go` accepts the same values as `next` — a section ID, `"done"`, or a URL.

---

## URL behavior

After the user submits the first section, the URL updates:

```
https://app.declarativeforms.com/{owner}/{repo}/rental?submission_id=abc123&step=property
```

`submission_id` identifies the in-progress submission. `step` is the `id` of the next section. This URL can be bookmarked or shared — revisiting it resumes the form from that section with previously entered data pre-populated.

---

## Localization

`title` and `description` accept a locale map instead of a plain string. When the form is loaded with a `lang` URL parameter, the matching locale is used; the first key is the fallback.

```yaml
  - id: personal
    title:
      en: Personal details
      fr: Informations personnelles
      es: Datos personales
```
