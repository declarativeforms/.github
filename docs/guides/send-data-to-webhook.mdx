---
title: Send data to a webhook
description: How to POST form submission data to your own API endpoint
---

A `webhook` connection sends the complete submission as a JSON POST request to a URL you specify.

## Configuration

```yaml
connections:
  - type: webhook
    url: https://your-api.com/hooks/form
```

## Payload

The request body is the full `ISubmission` object:

```json
{
  "id": "abc123",
  "form_id": "declarativeforms/examples/feedback",
  "status": "completed",
  "data": {
    "name": "Jane Smith",
    "email": "jane@example.com",
    "feedback": "Really helpful platform!"
  },
  "metadata": {
    "ip_address": "203.0.113.1",
    "user_agent": "Mozilla/5.0 ..."
  },
  "created_at": "2025-06-01T10:00:00Z",
  "updated_at": "2025-06-01T10:05:00Z"
}
```

The `data` object contains one key per field ID with the submitted value.

## Request headers

The POST request includes:

```
Content-Type: application/json
```

No authentication headers are sent. The webhook URL is the only credential.

## Timing

Webhook connections fire **only when the submission status is `completed`**—that is, when the user submits the final section. They do not fire for partial saves.

## Verifying the source

Since no auth headers are sent, use one or more of these approaches to validate the source:

1. **Secret in the URL** — include a secret token in the webhook path or query string: `https://your-api.com/hooks/form?token=secret123`
2. **Payload validation** — check that `status === "completed"` and `form_id` matches an expected value
3. **IP allowlist** — allowlist the platform's outbound IP addresses (check with support for the current list)

## Full example

```yaml
version: 1
title: Bug Report

sections:
  - id: report
    title: Report a bug
    fields:
      - id: summary
        type: short_text
        label: Summary
        validators:
          - required
      - id: steps
        type: long_text
        label: Steps to reproduce
      - id: severity
        type: single_select
        label: Severity
        options: [Low, Medium, High, Critical]
    next: done

connections:
  - type: webhook
    url: https://your-api.com/hooks/bugs?token=abc123
```

## Multiple webhooks

You can configure multiple webhook connections:

```yaml
connections:
  - type: webhook
    url: https://api.example.com/hooks/form
  - type: webhook
    url: https://zapier.com/hooks/catch/12345/abc
```

Both receive the same payload. Webhooks are processed sequentially.
