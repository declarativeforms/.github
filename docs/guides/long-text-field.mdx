---
title: Collect Long-Form Responses
description: Add a multi-line textarea for open-ended answers.
---

The `about_yourself` field lets applicants share context about themselves — a perfect use case for `long_text`, which renders a multi-line textarea.

---

## What to add

Add a `long_text` field to the `personal` section of `rental.yaml`:

```yaml
      - id: about_yourself
        type: long_text
        label: Tell us about yourself
        placeholder: Share anything relevant — lifestyle, work schedule, hobbies...
        validators:
          - required
          - type: min
            value: 50
```

---

## Field properties

| Property | Type | Description |
|----------|------|-------------|
| `id` | string | Unique identifier within the section. Becomes the key in submission data (e.g. `data.about_yourself`). Required. |
| `type` | string | Must be `long_text`. Required. |
| `label` | string or locale map | Displayed above the textarea. Required. |
| `placeholder` | string or locale map | Hint text shown inside the textarea when empty. Optional. |
| `validators` | array | Validation rules applied before the section can be submitted. Optional. |
| `visible_when` | string | JavaScript expression. Field is shown only when the expression evaluates to true. Optional. |

`long_text` renders a resizable multi-line textarea. Use it whenever you want the respondent to write more than a single line — descriptions, explanations, or open-ended responses.

---

## Validators

All validators run in the browser before the section is submitted. Multiple validators may be listed; all must pass.

### `required`

Field must not be empty before the section can be submitted.

```yaml
        validators:
          - required
```

The default error message is "This field is required." To override it:

```yaml
        validators:
          - type: required
            message: Please tell us about yourself.
```

### `type: min`

Minimum character count. Useful for encouraging substantive responses.

```yaml
        validators:
          - type: min
            value: 50
```

To override the default error message:

```yaml
        validators:
          - type: min
            value: 50
            message: Please write at least 50 characters.
```

### `type: max`

Maximum character count.

```yaml
        validators:
          - type: max
            value: 2000
```

To override the default error message:

```yaml
        validators:
          - type: max
            value: 2000
            message: Please keep your response under 2000 characters.
```

### `type: pattern`

Input must match a regular expression.

```yaml
        validators:
          - type: pattern
            regex: "^[^<>]+$"
```

Always include a `message` with pattern validators so the user understands what format is expected:

```yaml
        validators:
          - type: pattern
            regex: "^[^<>]+$"
            message: Response may not contain angle brackets.
```

## Localization

`label` and `placeholder` accept a locale map instead of a plain string. When the form is loaded with a `lang` URL parameter, the matching locale is used; the first key is the fallback.

```yaml
      - id: about_yourself
        type: long_text
        label:
          en: Tell us about yourself
          fr: Parlez-nous de vous
          es: Cuéntanos sobre ti
        placeholder:
          en: Share anything relevant — lifestyle, work schedule, hobbies...
          fr: Partagez tout ce qui est pertinent...
          es: Comparte lo que sea relevante...
```

---

## Conditional visibility

`visible_when` takes a JavaScript expression. The field is hidden when the expression is falsy and shown when it is truthy. The expression has access to all field values in the current section via the `fields` object.

```yaml
      - id: additional_notes
        type: long_text
        label: Additional notes
        visible_when: "fields.unit_type === '3br'"
```

Hidden fields are excluded from validation — a hidden required field will not block submission.
