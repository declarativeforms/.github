---
title: email
description: Email address input with format validation.
---

`email` renders a text input that validates the entered value as a correctly-formatted email address before the section is submitted.

**Submission value type:** `string` — the email address as entered, normalized to lowercase.

---

## Field properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `id` | `string` | Yes | Unique identifier within the form. Becomes the key in submission `data`. |
| `type` | `"email"` | Yes | Must be `email`. |
| `label` | `string \| LocaleMap` | Yes | Label shown above the input. |
| `placeholder` | `string \| LocaleMap` | No | Placeholder text shown inside the input when empty. |
| `otp` | `boolean` | No | When `true`, triggers email OTP verification before the section can be submitted. See [Verify Email Addresses](/guides/email-verification). |
| `validators` | `Validator[]` | No | Validation rules applied before the section is submitted. |
| `visible_when` | `string` | No | JS expression; field is shown when truthy, hidden otherwise. |

---

## Validators

### `required`

Field must not be empty and must be a valid email address format.

```yaml
validators:
  - required
```

Default error message: `This field is required.`

---

<Warning>
Validators run in the browser before each section is submitted. They enforce UX constraints, not security guarantees. If you need server-side validation, implement it in your webhook receiver.
</Warning>

---

## Full example

The `email` field from the rental application form with OTP verification enabled:

```yaml
version: 1
title: Rental Application
sections:
  - id: personal
    title: Personal details
    fields:
      - id: full_name
        type: short_text
        label: Full name
        validators:
          - required
      - id: email
        type: email
        label: Email address
        otp: true
        validators:
          - required
      - id: move_in_date
        type: date
        label: Desired move-in date
        validators:
          - required
    next: done
```
