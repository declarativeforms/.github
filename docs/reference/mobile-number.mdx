---
title: mobile_number
description: Phone number input with country code selector and format validation.
---

`mobile_number` renders a phone input with a country code selector. The applicant selects their country and enters their number; the field validates that it is a plausible mobile number for that country.

**Submission value type:** `string` in E.164 format (e.g., `+12025551234`).

---

## Field properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `id` | `string` | Yes | Unique identifier within the form. Becomes the key in submission `data`. |
| `type` | `"mobile_number"` | Yes | Must be `mobile_number`. |
| `label` | `string \| LocaleMap` | Yes | Label shown above the input. |
| `placeholder` | `string \| LocaleMap` | No | Placeholder text shown inside the input when empty. |
| `validators` | `Validator[]` | No | Validation rules applied before the section is submitted. |
| `visible_when` | `string` | No | JS expression; field is shown when truthy, hidden otherwise. |

---

## Validators

### `required`

A valid phone number must be entered.

```yaml
validators:
  - required
```

Default error message: `This field is required.`

---

<Warning>
Validators run in the browser before each section is submitted. They enforce UX constraints, not security guarantees. If you need server-side validation, implement it in your webhook receiver.
</Warning>

---

## Full example

The `phone` field from the rental application form's personal section:

```yaml
version: 1
title: Rental Application
sections:
  - id: personal
    title: Personal details
    fields:
      - id: phone
        type: mobile_number
        label: Phone number
        validators:
          - required
    next: done
```
