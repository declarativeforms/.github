All support for Declarative Forms runs through GitHub Issues.

We aim to respond to issues within 24 hours.

---

## Before you open an issue

Include these first:

1. **Form URL** - where the behavior occurs
2. **YAML snippet** - relevant section (remove sensitive data)
3. **Expected behavior** - what should happen
4. **Actual behavior** - what happened instead
5. **Reproduction steps** - numbered steps anyone can follow
6. **Browser and OS** - for example, Chrome on macOS

This is the fastest path to a fix.

---

## The 48-hour feature promise

For well-scoped requests that clearly improve the product for more than one user, we target shipping within 48 hours.

This is a target for requests that are clear, broadly useful, and small enough to act on safely.

Open a [feature request issue](https://github.com/declarativeforms/.github/issues/new) and include:

1. **Use case** - what you are trying to do
2. **Current workaround** - what you do today
3. **Impact** - why this matters for your workflow

We optimize for the underlying problem, not just the proposed implementation.

---

## Report a bug

Open a [bug issue](https://github.com/declarativeforms/.github/issues/new) with the checklist above.

If possible, include a minimal public repository that reproduces the issue.

---
