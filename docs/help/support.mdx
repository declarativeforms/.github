## The 48-hour promise

Most form platforms have feature request boards where ideas sit for months. We do things differently.

Open a [GitHub Issue](https://github.com/declarativeforms/examples/issues) with your feature request—if it genuinely improves the product, we'll ship it within 48 hours. No waitlists, no roadmap purgatory, no "we'll consider it."

---

## Report a bug

[Open a GitHub Issue](https://github.com/declarativeforms/examples/issues/new) with:

1. **Form URL** — the URL where the issue occurs (or a minimal reproduction in a public repo)
2. **Expected behavior** — what should happen
3. **Actual behavior** — what actually happens
4. **Steps to reproduce** — numbered list of steps
5. **Browser and OS** — e.g., "Chrome 120 on macOS 14"
6. **YAML snippet** — the relevant portion of your form config (remove any sensitive data)

---

## Request a feature

[Open a GitHub Issue](https://github.com/declarativeforms/examples/issues/new) with:

1. **What you want to do** — describe the use case, not just the feature
2. **Current workaround** — what you're doing today instead
3. **Why it matters** — how it would help you or your team

Good feature requests focus on the problem, not a specific solution. We'll often find a better way to solve the underlying need.

---

## Ask a question

For questions about how something works:

1. Check the [FAQ](/help/faq) and [Troubleshooting](/help/troubleshooting) pages first
2. If you can't find an answer, [open a GitHub Issue](https://github.com/declarativeforms/examples/issues/new) with the `question` label

---
