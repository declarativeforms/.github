---
title: Sections
description: How sections divide a form into steps and control navigation.
---

Sections divide a form into discrete steps. The platform presents one section at a time — the user completes it, then moves to the next. At minimum, a section needs an identifier, a title, fields, and a navigation target.

```yaml
sections:
  - id: contact
    title: Contact Information
    fields:
      - id: name
        type: short_text
        label: Name
        validators:
          - required
      - id: email
        type: email
        label: Email
        validators:
          - required
    next: done
```

- **`id`** — A unique identifier for the section. Used in navigation targets and the `?step=` URL parameter.
- **`title`** — The heading displayed above the section's fields.
- **`fields`** — An ordered array of field definitions. See [Fields](/concepts/fields).
- **`next`** — Determines what happens when the user submits this section.

---

## Ending the form

The simplest navigation — `next: done` submits the form and displays the [completion screen](/concepts/completion).

```yaml
next: done
```

- **`done`** — A reserved keyword. Submits the form data and shows the completion screen.

---

## Navigating to another section

For multi-step forms, `next` points to the `id` of the next section.

```yaml
sections:
  - id: contact
    title: Contact Details
    fields:
      # ...
    next: preferences

  - id: preferences
    title: Your Preferences
    fields:
      # ...
    next: done
```

- **`next`** — The `id` of the section to navigate to. The form advances to that section when the user submits the current one.

---

## External redirect

You can redirect to an external URL instead of continuing the form.

```yaml
next: "https://example.com/thank-you"
```

- **`next`** — Any value starting with `https://` triggers a browser redirect. No completion screen is shown.

---

## Conditional navigation

For branching logic, `next` accepts an array of rules evaluated in order.

```yaml
next:
  - when: data.attending == 'Yes'
    go: event_details
  - when: data.attending == 'Maybe'
    go: follow_up
  - else: done
```

- **`when`** — A JavaScript expression evaluated against the submitted form data.
- **`go`** — The section `id` to navigate to if the expression is true.
- **`else`** — A fallback destination used when no `when` rule matches.

Rules are evaluated in order — the first match wins. The `data` object contains all submitted field values keyed by `id`. If no rule matches and there is no `else`, the form ends.

---

## Resuming mid-form

When a form has multiple sections, the URL updates with `?step=` and `?submission_id=` as the user progresses. This allows the user to bookmark or share a mid-form URL and resume where they left off.
