---
title: Prefilling Fields
---

Prefilling fields lets a form open with known values already populated from the URL. Use it when you want to personalize a link, carry values in from another system, or start the form with information you already have.

## Overview

Prefilling works through the URL query string. Every non-reserved query parameter is copied into the form's initial data, where the parameter name matches the field id and the parameter value becomes the field's initial value.

These values are available from the first render. This means prefills can affect any feature that reads the current form data on load, including template interpolation and expression-based behavior such as conditional visibility.

## Structure

```text
https://frms.dev/frm_123?email=hello@example.com&first_name=Taylor
```

```text
https://frms.dev/acme/octocat/feedback?email=hello@example.com
```

On slug routes, the app resolves the form id and preserves the query parameters during the redirect.

## Fields

<ParamField path="<field_id>" type="string">
  Defines the query parameter used to prefill the matching field.
</ParamField>

## Details

The query parameter name must match the field `id`.

Prefilled values are treated as the initial form data only.

The reserved query parameters `connection_id`, `lang`, `submission_id`, and `step` are excluded from prefilling.

Query parameter values are read as strings.

Prefilled values become part of `data`, so they can affect interpolated labels, placeholders, titles, descriptions, completion content, and expression-based logic from the first render.
