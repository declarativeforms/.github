title: Fields
description: The shared anatomy of a field — type, label, and optional modifiers.
---

Fields are the inputs inside a section. Every field has a type that determines how it renders, but all fields share a common set of properties. At minimum, a field needs an identifier, a type, and a label.

```yaml
- id: name
  type: short_text
  label: Full Name
```

- **`id`** — A unique identifier within the form. This becomes the key in the submitted data (e.g., `{ "name": "Jane" }`). Also used for [prefill](#prefill) and [Handlebars templating](/concepts/completion) via `{{data.id}}`.
- **`type`** — Determines the input's rendering and behavior. See [Field types](#field-types) below.
- **`label`** — The text displayed above the input.

---

## Placeholder

An optional hint shown inside the input when it is empty.

```yaml
- id: email
  type: email
  label: Email
  placeholder: jane@example.com
```

- **`placeholder`** — Hint text displayed when the input is empty.

---

## Conditional visibility

The `visible_when` property controls whether a field appears. It accepts a JavaScript expression evaluated against the current form data.

```yaml
- id: delivery_address
  type: address
  label: Delivery Address
  visible_when: data.fulfillment === 'Delivery'
```

- **`visible_when`** — A JavaScript expression. When it evaluates to `false` (or any falsy value), the field is hidden and excluded from validation.

The `data` object contains the live values of all fields in the form, keyed by their `id`.

## Prefill

You can set a field's initial value using URL query parameters. The parameter name matches the field's `id`.

```
https://app.declarativeforms.com/acme/forms/signup?email=jane@example.com
```

This sets the initial value of the field with `id: email` to `jane@example.com`. Prefill is especially useful with [hidden fields](/reference/hidden) for tracking attribution.

A small set of parameter names are reserved by the platform and cannot be used for prefill:

| Parameter | Purpose |
|---|---|
| `lang` | Sets the display language. See [Localization](/concepts/localization). |
| `step` | Resumes the form at a specific section by its `id`. |
| `submission_id` | Continues an existing submission instead of creating a new one. |
| `connection_id` | Identifies an OAuth connection for integrations like Airtable. |

## Field types

Each type determines the input's rendering, behavior, and how [validators](/concepts/validators) apply.

| Type | Description |
|---|---|
| `short_text` | Single-line text input. |
| `long_text` | Multi-line textarea. |
| `email` | Email input. Supports [OTP verification](/reference/email) with `otp: true`. |
| `number` | Whole-number input. Numeric keyboard on mobile. |
| `date` | Date picker. |
| `url` | URL input. |
| `mobile_number` | Phone number input. |
| `dropdown` | Select menu. Supports `searchable: true` for a filterable combobox. |
| `single_select` | Radio-style single choice from `options`. |
| `multiple_select` | Checkbox-style multiple choice from `options`. |
| `rating` | Numeric scale (default 1–5). Supports `min_label` and `max_label`. |
| `file_upload` | Drag-and-drop file attachment. |
| `signature` | Canvas-based drawing. Automatically uploads as PNG. |
| `address` | Google Places autocomplete for full addresses. |
| `address_locality` | Google Places filtered to cities. |
| `address_region` | Google Places filtered to administrative regions. |
| `address_country` | Google Places filtered to countries. |
| `geolocation` | Captures the user's location via the browser Geolocation API. |
| `hidden` | Invisible field. Value set via [prefill](#prefill) matching the field `id`. |

See the [Reference](/reference/short-text) pages for the full specification of each type.
