A Declarative Form is a single YAML file that describes what your form looks like, how it behaves, and where its data goes. You define the structure — the platform handles rendering, validation, and submission.

---

## Building blocks

Every form is assembled from a small set of concepts. Here is how they relate:

```
Form
├── Sections
│   └── Fields
│       └── Validators
└── Connections
```

**[Form](/concepts/form)** — The top-level container. Defines the form's identity with a version, title, and description.

**[Sections](/concepts/sections)** — Divide the form into steps. Each section contains fields and controls what happens when the user submits it.

**[Fields](/concepts/fields)** — The inputs your users interact with. Each field has a type, a label, and optional modifiers like conditional visibility and URL prefill.

**[Validators](/concepts/validators)** — Rules that enforce constraints on field values. Required, minimum, maximum, and pattern.

**[Connections](/concepts/connections)** — Integrations that fire when the form is submitted. Webhook, email, and Airtable.

---

## Customization

Once you have the core structure in place, these concepts let you refine the experience:

**[Completion](/concepts/completion)** — Customize the thank-you screen shown after submission.

**[Localization](/concepts/localization)** — Translate any text property into multiple languages using locale maps.

**[Scheduling](/concepts/scheduling)** — Restrict a form to a specific time window.

**[Analytics](/concepts/analytics)** — Track form views and section completions with Mixpanel.
