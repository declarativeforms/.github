---
title: Connections
description: How to receive submission data after a form is completed.
---

After `feedback.yaml` is submitted, how do you receive the data? That's what connections are for.

Connections are configured in the `connections` array at the top level of your YAML file. They fire once, when the submission status becomes `completed` — that is, when the user submits the final section.

---

## Adding a webhook to the canonical form

```yaml
version: 1
title: Feedback
sections:
  - id: main
    title: Share your feedback
    fields:
      - id: name
        type: short_text
        label: Your name
      - id: message
        type: short_text
        label: Your message
    next: done

connections:
  - type: webhook
    url: https://your-api.com/hooks/feedback
```

When the form is completed, the platform sends an HTTP POST to `https://your-api.com/hooks/feedback`.

---

## What the webhook body looks like

The request body is the full submission object:

```json
{
  "id": "abc123",
  "form_id": "acme/forms/feedback",
  "status": "completed",
  "data": {
    "name": "Jane Smith",
    "message": "The product is great. More keyboard shortcuts please."
  },
  "metadata": {
    "ip_address": "203.0.113.1",
    "user_agent": "Mozilla/5.0 ..."
  },
  "created_at": "2025-06-01T10:00:00Z",
  "updated_at": "2025-06-01T10:05:00Z"
}
```

No authentication headers are sent. To verify the source, validate the payload structure in your receiver, or embed a secret in your webhook URL.

## Email connections

Send an email when the form is completed. Supports Handlebars-style variables:

```yaml
connections:
  - type: email
    to: "{{data.name}} <team@example.com>"
    subject: "New feedback from {{data.name}}"
    body: "<p>{{data.message}}</p>"
    include_responses: true
```

Setting `include_responses: true` appends an auto-generated table of all field responses to the email body.

---

## Airtable connections

Create a new row in an Airtable base. Requires an OAuth connection set up through the [connections page](https://app.declarativeforms.com/connections).

```yaml
connections:
  - type: airtable
    connection_id: your-airtable-connection-id
    base_id: appXXXXXXXXXXXXXX
    table_id_or_name: Submissions
```

Your form field IDs (`name`, `message`) must match Airtable column names exactly.

---

## Connections fire on completed submissions only

Connections are not triggered for partial saves. If a user submits section 1 of a multi-section form and then abandons it, no connections fire. They only fire when `status` becomes `completed`.
