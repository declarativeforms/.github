title: Connections
description: Overview of webhook, email, and Airtable connections
---

Connections define what happens after a form is **completed**. They are configured in the `connections` array at the top level of your YAML file.

```yaml
connections:
  - type: webhook
    url: https://your-api.com/hooks/form
  - type: email
    to: team@example.com
    subject: New submission
    include_responses: true
```

## Important: connections fire on final submission only

Connections are **not** triggered for partial submissions (i.e., mid-form section saves). They fire once, when the submission status becomes `completed`—that is, when the user submits the final section of the form.

## Connection types

### Webhook

Sends the full submission as JSON to your endpoint via HTTP POST.

```yaml
- type: webhook
  url: https://your-api.com/hooks/form
```

The request body is the complete `ISubmission` object. See [Webhook connection reference](/reference/connections#webhook) for the full payload shape.

No authentication headers are sent with the request. To verify the source, validate the payload structure in your receiver, or use a secret in your webhook URL.

### Email

Sends an email via [Resend](https://resend.com). Supports Handlebars-style template variables in `to`, `subject`, and `body`.

```yaml
- type: email
  to: "{{data.email}}"
  subject: "Thanks for your submission, {{data.name}}!"
  body: "<p>We received your message and will be in touch soon.</p>"
  include_responses: true
```

Setting `include_responses: true` appends an auto-generated HTML table of all non-hidden field responses to the email body.

### Airtable

Creates a new record in an Airtable base. Requires an OAuth connection set up through the [connections page](https://app.declarativeforms.com/connections).

```yaml
- type: airtable
  connection_id: your-airtable-connection-id
  base_id: appXXXXXXXXXXXXXX
  table_id_or_name: Submissions
```

The `submission.data` object is sent directly as Airtable `fields`. Your form field IDs must match Airtable column names exactly.

## Multiple connections

You can configure multiple connections on a single form. They are processed sequentially in the order they appear in the `connections` array.

```yaml
connections:
  - type: email
    to: "{{data.email}}"
    subject: Your submission was received
    body: "<p>Thank you, {{data.name}}.</p>"

  - type: email
    to: admin@example.com
    subject: New form submission
    include_responses: true

  - type: webhook
    url: https://your-api.com/hooks/form

  - type: airtable
    connection_id: abc123
    base_id: appXXXXXXXXXXXXXX
    table_id_or_name: Leads
```
