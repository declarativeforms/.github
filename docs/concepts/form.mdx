title: Form

A form is a YAML file that contains everything the platform needs to render and process a set of inputs. At minimum, it requires a schema version, a title, and one or more sections.

```yaml
version: 1
title: Registration Form
description: Sign up for early access.

sections:
  - id: signup
    title: Your Details
    fields:
      - id: email
        type: email
        label: Email
        validators:
          - required
    next: done
```

- **`version`** — Always `1`. Identifies the schema version.
- **`title`** — The name displayed at the top of the form. [Localizable](/concepts/localization).
- **`description`** — An optional subtitle shown below the title. [Localizable](/concepts/localization).
- **`sections`** — The form's content, defined as an ordered array. See [Sections](/concepts/sections).
- **`connections`** — An optional array of integrations triggered on submission. See [Connections](/concepts/connections).

## Completion screen

When the form is submitted, the platform shows a default thank-you page. The `completion` property lets you customize it.

```yaml
completion:
  title: "Thanks, {{data.name}}!"
  message: We'll be in touch within 24 hours.
  button:
    label: Visit our website
    url: https://example.com
```

- **`title`** — The heading on the completion page. Supports Handlebars templating — `{{data.fieldId}}` is replaced with the submitted value.
- **`message`** — Body text below the title. Also supports templating.
- **`button`** — An optional call-to-action with a `label` and `url`. Both support templating.

All three properties are [localizable](/concepts/localization).

## Scheduling

You can restrict a form to a specific time window using `start_date` and `end_date`.

```yaml
start_date: "2026-03-01"
end_date: "2026-03-31"
```

- **`start_date`** — The earliest date the form accepts submissions. Visitors who arrive before this date see a "form not yet open" message.
- **`end_date`** — The latest date the form accepts submissions. Visitors who arrive after this date see a "form closed" message.

Both values are ISO 8601 date strings. You can use either property independently.

## URL parameters

When a form loads in the browser, query parameters control its runtime behavior.

### Reserved parameters

These parameters are handled by the platform and cannot be used for prefill.

| Parameter | Purpose |
|---|---|
| `lang` | Sets the display language. See [Localization](/concepts/localization). |
| `step` | Resumes the form at a specific section by its `id`. |
| `submission_id` | Continues an existing submission instead of creating a new one. |
| `connection_id` | Identifies an OAuth connection for integrations like Airtable. |

### Prefill

Any query parameter that is not reserved prefills a field whose `id` matches the parameter name.

```
https://app.declarativeforms.com/acme/forms/signup?email=jane@example.com
```

This sets the initial value of the field with `id: email` to `jane@example.com`. Prefill is especially useful with [hidden fields](/reference/hidden) for tracking attribution.
