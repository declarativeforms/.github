---
title: Sections and Navigation
description: How sections, fields, and navigation work — from a single section to conditional branching.
---

Every form is made up of one or more **sections**. Each section is a discrete step with its own set of fields. This page builds from a single section up to conditional navigation.

---

## What is a section?

The canonical `feedback.yaml` has one section:

```yaml
sections:
  - id: main
    title: Share your feedback
    fields:
      - id: name
        type: short_text
        label: Your name
      - id: message
        type: short_text
        label: Your message
    next: done
```

A section has four required properties: `id`, `title`, `fields`, and `next`.

---

## What is a field?

Fields are the inputs inside a section. Each field needs at minimum an `id`, a `type`, and a `label`:

```yaml
- id: name
  type: short_text
  label: Your name
```

`id` is how the value appears in submission data. `type` controls what kind of input renders. `label` is what the user sees.

---

## What does `next: done` mean?

`done` is a reserved value that ends the form. When the user submits a section with `next: done`, the submission is marked `completed` and the thank-you page appears.

---

## Adding a second section

Split the canonical form into two steps by adding a second section and pointing the first to it:

```yaml
sections:
  - id: about
    title: About you
    fields:
      - id: name
        type: short_text
        label: Your name
    next: feedback

  - id: feedback
    title: Share your feedback
    fields:
      - id: message
        type: short_text
        label: Your message
    next: done
```

The form starts at the first section in the array (`about`). After submission it advances to `feedback`, then ends.

---

## `next` pointing to a section ID

`next` can be any section's `id`, the string `"done"`, or an `https://` URL (to redirect the user after the section):

```yaml
next: feedback          # advance to the section with id "feedback"
next: done              # end the form
next: https://example.com/thank-you  # redirect instead of showing the thank-you page
```

---

## Conditional `next`

To send different users to different sections based on their answers, use an array of `when/go` rules with a required `else` fallback:

```yaml
sections:
  - id: about
    title: About you
    fields:
      - id: name
        type: short_text
        label: Your name
      - id: role
        type: short_text
        label: Your role
    next:
      - when: "data.role === 'manager'"
        go: manager_feedback
      - else: feedback

  - id: feedback
    title: Share your feedback
    fields:
      - id: message
        type: short_text
        label: Your message
    next: done

  - id: manager_feedback
    title: Manager feedback
    fields:
      - id: message
        type: short_text
        label: What would help your team?
    next: done
```

Rules are evaluated in order. The first matching `when` wins. `else` is required and serves as the fallback.

`when` values are JavaScript expressions evaluated against `data`, an object containing all field values collected so far.

---

## `visible_when` on a field

To show or hide a specific field based on other answers, use `visible_when` on the field definition:

```yaml
fields:
  - id: name
    type: short_text
    label: Your name
  - id: message
    type: short_text
    label: Your message
    visible_when: "data.name !== ''"
```

`visible_when` is a JavaScript expression. The field renders when the expression is truthy and is hidden otherwise. Hidden fields are excluded from submission data.
