title: Submissions

When a user submits `feedback.yaml`, the platform creates a submission record. This page shows exactly what that record looks like and how it changes through the form flow.

---

## What gets saved

For the canonical `feedback.yaml` — two `short_text` fields, `name` and `message` — a completed submission looks like this:

```json
{
  "id": "abc123",
  "form_id": "acme/forms/feedback",
  "status": "completed",
  "data": {
    "name": "Jane Smith",
    "message": "The product is great. More keyboard shortcuts please."
  },
  "metadata": {
    "ip_address": "203.0.113.1",
    "user_agent": "Mozilla/5.0 ..."
  },
  "created_at": "2025-06-01T10:00:00Z",
  "updated_at": "2025-06-01T10:05:00Z"
}
```

`data` contains one key per field ID, with the user's submitted value. `metadata` is populated automatically.

---

## `status: "partial"` vs `status: "completed"`

For a single-section form like `feedback.yaml`, the submission goes directly to `completed` when the user submits. There is no intermediate state.

For a multi-section form, the status moves through two states:

| Status | When | Connections fire? |
|--------|------|-------------------|
| `partial` | After each section (except the last) | No |
| `completed` | After the final section | Yes |

Here's what the submission looks like mid-way through the two-section variant of the form — after `about` has been submitted but before `feedback`:

```json
{
  "id": "abc123",
  "form_id": "acme/forms/feedback",
  "status": "partial",
  "data": {
    "name": "Jane Smith"
  },
  "metadata": { ... },
  "created_at": "2025-06-01T10:00:00Z",
  "updated_at": "2025-06-01T10:02:00Z"
}
```

After the user completes the second section, `status` becomes `completed` and `data.message` is added.

---

## `metadata`

Every submission includes two automatically populated fields:

- `metadata.ip_address` — the IP address of the submitting browser
- `metadata.user_agent` — the browser's user agent string

These cannot be set by the user.

---

## Resume: how `?submission_id=` and `?step=` work

After each section is submitted, the platform writes the submission ID and the next section ID into the URL:

```
https://app.declarativeforms.com/acme/forms/feedback?submission_id=abc123&step=feedback
```

This happens automatically. The user can bookmark this URL and return later. When they do, the platform loads the existing partial submission and resumes from the saved step, with previously entered values pre-populated.

For single-section forms like the canonical `feedback.yaml`, this URL is never generated — the form completes in one step.
