title: Localization
description: How to translate forms into multiple languages
---

Declarative Forms supports multiple languages through locale maps in your YAML configuration.

## Supported locales

| Code | Language |
|------|----------|
| `en` | English |
| `es` | Spanish |

## Locale resolution priority

The active locale is determined in this order:

1. `?lang=` query parameter (e.g., `?lang=es`)
2. Browser's `navigator.language`
3. `locale` key in the YAML
4. English (`en`) as the final fallback

## Locale map syntax

Any text field that supports localization accepts either a plain string or an object where the keys are locale codes:

```yaml
# Plain string (applies to all locales)
title: My Form

# Locale map
title:
  en: My Form
  es: Mi formulario
```

## Fields that support locale maps

The following fields accept locale maps:

| Field | Notes |
|-------|-------|
| Form `title` | Top-level key |
| Form `description` | Top-level key |
| Section `title` | Per-section |
| Field `label` | Per-field |
| Field `placeholder` | Per-field |
| Option `label` | For dropdown, single_select, multiple_select, rating |
| Validator `message` | Custom error message per validator |
| `completion.title` | Thank-you page title |
| `completion.message` | Thank-you page body |
| `completion.button.label` | Button label |
| `completion.button.url` | Button URL (can vary by locale) |
| Email connection `subject` | Per connection |
| Email connection `body` | Per connection |

## Locking a form to a specific locale

Set the `locale` top-level key to force all users into a specific language:

```yaml
version: 1
locale: es
title:
  en: Contact Us
  es: Contáctanos
sections:
  - id: main
    title:
      en: Your message
      es: Tu mensaje
    fields:
      - id: name
        type: short_text
        label:
          en: Full name
          es: Nombre completo
    next: done
```

When `locale` is set in the YAML, the platform automatically adds `?lang=es` to the URL if it's not already present. This keeps the locale consistent even when users navigate between sections.

<Note>
The `?lang=` parameter always takes precedence over the YAML `locale` key. This allows you to override the form locale from a link (e.g., for multilingual marketing campaigns).
</Note>

## Translating option labels

For selection fields, use the structured option format with a `label` locale map:

```yaml
- id: country
  type: dropdown
  label:
    en: Country
    es: País
  options:
    - value: us
      label:
        en: United States
        es: Estados Unidos
    - value: mx
      label:
        en: Mexico
        es: México
    - value: es
      label:
        en: Spain
        es: España
```

The `value` is what gets stored in the submission—not the translated label. This means your submission data is locale-independent regardless of the user's language.
