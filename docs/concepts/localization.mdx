---
title: Localization
description: How to translate form text into multiple languages.
---

Any text property in a form definition can be translated. Instead of a plain string, you provide an object keyed by language code. The platform resolves which language to display at runtime.

```yaml
version: 1
title:
  en: Registration Form
  es: Formulario de registro
locale: en

sections:
  - id: signup
    title:
      en: Your Details
      es: Tus datos
    fields:
      - id: name
        type: short_text
        label:
          en: Full Name
          es: Nombre completo
    next: done
```

- **`locale`** — The default language for the form. Used when no `?lang=` parameter is present.

---

## Localized text

Text properties accept two formats — a plain string or a locale map.

```yaml
# Plain string — renders as-is regardless of language.
title: Registration Form

# Locale map — renders the value matching the active language.
title:
  en: Registration Form
  es: Formulario de registro
  fr: Formulaire d'inscription
```

You can mix both formats in the same form. Localize the properties that need translation and leave others as plain strings.

---

## Where it applies

The following properties accept localized text:

- **[Form](/concepts/form)** — `title`, `description`
- **[Section](/concepts/sections)** — `title`
- **[Field](/concepts/fields)** — `label`, `placeholder`
- **Options** — `label` (on `dropdown`, `single_select`, `multiple_select` options)
- **[Validators](/concepts/validators)** — `message` (on `min`, `max`, `pattern`)
- **[Completion](/concepts/completion)** — `title`, `message`, `button.label`, `button.url`
- **[Email connection](/concepts/connections#email)** — `subject`, `body`

---

## Runtime switching

You override the default locale at runtime with the `?lang=` query parameter.

```
https://app.declarativeforms.com/acme/forms/booking?lang=es
```

The platform resolves the language in this order:

1. `?lang=` query parameter (if present)
2. `locale` form property (if set)
3. `en` fallback

Locale matching is flexible — if the exact code is not found (e.g., `en-US`), the platform tries the base language (`en`) before falling back.
