---
title: Localization
---

Localization lets a form define its default locale and provide translated content for supported text values. Use it when the same form should present different copy across different languages.

## Overview

Localization has two parts. The form-level `locale` property defines the default locale used across the form, while localized text objects let you provide multiple translations for the same piece of content.

A localized text object is a map where each key is a locale code and each value is the text for that locale. This pattern can be used anywhere the schema supports `string | object`, such as titles, descriptions, labels, placeholders, validator messages, completion content, and email connection content.

## Structure

```yaml
locale: "en"

title:
  en: "Feedback"
  fr: "Retour"

sections:
  - id: contact
    title:
      en: "Contact"
      fr: "Contact"
    fields:
      - id: email
        type: email
        label:
          en: "What's your email?"
          fr: "Quelle est votre adresse e-mail ?"
        placeholder:
          en: "hello@example.com"
          fr: "bonjour@example.com"
        validators:
          - type: pattern
            regex: ".+@.+"
            message:
              en: "Please enter a valid email."
              fr: "Veuillez saisir une adresse e-mail valide."
    next: done

completion:
  title:
    en: "Thank you!"
    fr: "Merci !"
```

## Fields

<ParamField path="locale" type="string">
  Defines the default locale used to resolve localized content across the form.
</ParamField>

<ParamField path="<locale>" type="string">
  Defines the text used for the given locale code.
</ParamField>

## Details

Localized text objects are dynamic maps and can use any locale code as a key.

Localized values are resolved by exact locale first, then by base locale, then by `en`, and finally by the first non-empty value.

When the form defines `locale`, the form and thank-you pages keep the `lang` query parameter aligned with that value.
