---
title: Expressions
---

Expressions define conditional logic in a form. Use them when visibility, navigation, or validation should depend on the respondent's answers.

## Overview

Expressions are conditions evaluated against the current form data. They use `data` as the input object, where each field value is available by its field id.

The same expression model is used across the platform. It powers [conditional visibility](/concepts/conditional_visibility), [conditional navigation](/concepts/conditional_navigation), and expression-based [validators](/concepts/validators).

## Structure

```yaml
visible_when: data.contact_method === "email"

validators:
  - type: expression
    expression: data.age >= 18
    message: "You must be 18 or older."

next:
  - when: data.plan === "enterprise"
    go: sales
  - else: done
```

## Fields

<ParamField path="<expression>" type="string">
  Defines a condition evaluated against the current form data.
</ParamField>

<ParamField path="data.<field_id>" type="unknown">
  Defines the value of a submitted field within an expression.
</ParamField>

## Details

Expressions are evaluated against the current form data and should resolve to `true` or `false`.

If an expression cannot be evaluated, it is treated as not matched.
