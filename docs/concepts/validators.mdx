---
title: Validators
---

Validators define the rules a field value must satisfy before the current section can continue. Use them when a field should be required, constrained, or checked against a custom condition.

## Overview

Validators are defined inside a field's `validators` array. The array can contain the literal `required` validator or object-based validators with their own properties, depending on the kind of check you need.

Most validators apply the same way across fields, while `min` and `max` change meaning depending on the field type. This lets the same validator model cover text, dates, numbers, files, selections, and custom expression-based checks.

Where a validator supports `message`, it can use `string | object` and follows the same localization model as other form content.

Number fields also apply a whole-number check when no custom `pattern` validator is provided.

## Structure

```yaml
validators:
  - required
  - type: min_length
    value: 3
  - type: expression
    expression: data.age >= 18
    message: "You must be 18 or older."
```

## `required`

Use `required` when the respondent must provide a value before the form can continue.

### Structure

```yaml
validators:
  - required
```

### Fields

<ParamField path="required" type="string">
  Defines the validator as a required-value check.
</ParamField>

### Details

The `required` validator checks that the field has a non-empty value before the current section can be submitted.

Its validation message is generated automatically from the field label.

## `pattern`

Use `pattern` when the field value should match a specific regular expression.

### Structure

```yaml
validators:
  - type: pattern
    regex: "^[A-Z]{3}$"
    message: "Use exactly three uppercase letters."
```

### Fields

<ParamField path="type" type="pattern">
  Defines the validator as a pattern check.
</ParamField>

<ParamField path="regex" type="string">
  Defines the regular expression used to validate the field value.
</ParamField>

<ParamField path="message" type="string | object">
  Defines the message shown when the validation fails.
</ParamField>

### Details

When `message` is not provided, the platform uses a default invalid-value message.

## `min`

Use `min` when a field should not allow values below a lower bound.

### Structure

```yaml
validators:
  - type: min
    value: 1
```

### Fields

<ParamField path="type" type="min">
  Defines the validator as a minimum value check.
</ParamField>

<ParamField path="value" type="number | string">
  Defines the minimum value allowed by the validator.
</ParamField>

<ParamField path="message" type="string | object">
  Defines the message shown when the validation fails.
</ParamField>

### Details

The meaning of `min` depends on the field type. For `date`, it defines the earliest allowed date. For `number`, it defines the minimum numeric value. For `rating`, it defines the minimum allowed rating. For `file_upload`, it defines the minimum number of files. For `multiple_select`, it defines the minimum number of selected options.

When `message` is not provided, the platform uses a default field-specific minimum message.

For `rating`, the platform defaults to a minimum of `1` when no valid `min` is provided.

## `expression`

Use `expression` when validation should depend on a custom condition evaluated against the current form data.

### Structure

```yaml
validators:
  - type: expression
    expression: data.age >= 18
    message: "You must be 18 or older."
```

### Fields

<ParamField path="type" type="expression">
  Defines the validator as an expression-based check.
</ParamField>

<ParamField path="expression" type="string">
  Defines the expression that must return `true` for validation to pass.
</ParamField>

<ParamField path="message" type="string | object">
  Defines the message shown when the validation fails.
</ParamField>

### Details

The `message` property is required for this validator.

The expression is evaluated against the current form data. See [expressions](/concepts/expressions) for more details.

If the expression returns `false` or cannot be evaluated, validation fails.
