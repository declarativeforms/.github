---
title: Route people to different next steps
description: Send people to different sections based on what they choose in a public GitHub repository.
---

Make a multi-step form branch in different directions. By the end of this guide, your form will send sales inquiries to one step and support inquiries to another, while keeping the same email connection sending completed submissions to you.

Start from the `contact.yaml` form in the multi-step guide and keep it in a public GitHub repository on the `main` branch.

## Start with

Start with a simple multi-step structure:

```yaml
sections:
  - id: contact_details
    title: "Your details"
    fields:
      - id: full_name
        type: short_text
        label: "Full name"
        validators:
          - required

      - id: email
        type: email
        label: "Email address"
        validators:
          - required

      - id: message
        type: long_text
        label: "Message"
        validators:
          - required

    next: done
```

In this version, everyone follows the same path.

## Build it

Add a field that asks what kind of inquiry this is:

```yaml
      - id: inquiry_type
        type: single_select
        label: "What do you need help with?"
        options:
          - Sales
          - Support
        validators:
          - required
```

Then split the form into two follow-up sections and route to them with `next` rules:

```yaml
    next:
      - when: data.inquiry_type === "Sales"
        go: sales_details
      - else: support_details

  - id: sales_details
    title: "Sales details"
    fields:
      - id: team_size
        type: short_text
        label: "How large is your team?"
      - id: sales_message
        type: long_text
        label: "What are you looking for?"
        validators:
          - required

    next: done

  - id: support_details
    title: "Support details"
    fields:
      - id: account_email
        type: email
        label: "Account email"
        validators:
          - required
      - id: support_message
        type: long_text
        label: "What do you need help with?"
        validators:
          - required

    next: done
```

When someone chooses **Sales**, the form goes to `sales_details`. Otherwise it goes to `support_details`.

Keep the same email connection:

```yaml
connections:
  - type: email
    to: "hello@example.com"
    subject: "New contact form submission"
    include_responses: true
```

## Final version

Your full `contact.yaml` file should now look like this:

```yaml
version: 1
title: "Contact us"
description: "Send us a message and we will get back to you."

sections:
  - id: contact_details
    title: "Your details"
    fields:
      - id: full_name
        type: short_text
        label: "Full name"
        validators:
          - required

      - id: email
        type: email
        label: "Email address"
        validators:
          - required

      - id: inquiry_type
        type: single_select
        label: "What do you need help with?"
        options:
          - Sales
          - Support
        validators:
          - required

    next:
      - when: data.inquiry_type === "Sales"
        go: sales_details
      - else: support_details

  - id: sales_details
    title: "Sales details"
    fields:
      - id: team_size
        type: short_text
        label: "How large is your team?"
      - id: sales_message
        type: long_text
        label: "What are you looking for?"
        validators:
          - required

    next: done

  - id: support_details
    title: "Support details"
    fields:
      - id: account_email
        type: email
        label: "Account email"
        validators:
          - required
      - id: support_message
        type: long_text
        label: "What do you need help with?"
        validators:
          - required

    next: done

connections:
  - type: email
    to: "hello@example.com"
    subject: "New contact form submission"
    include_responses: true
```

## Try it

Commit the updated `contact.yaml` file to the `main` branch, then open:

`https://frms.dev/<owner>/<repo>/contact`

Replace `<owner>` with your GitHub username or organization, and `<repo>` with your repository name.

Open the form and test both paths. If you choose **Sales**, the form should go to the sales step. If you choose **Support**, it should go to the support step. Each path should submit successfully and still send the submission email.
