This guide shows the simplest way to publish a form with Declarative Forms.

You’ll define a form in a single YAML file, push it to your repository, and access it instantly through a generated URL.

No dashboard configuration. No setup panels. Just structure.

---

## 1. Create a YAML file

Inside your repository, create a new file.
You can name it anything you like — for example:

```
basic.yaml
```

Add the following:

```yaml
version: 1
title: "Basic Example"
description: "Lorem ipsum dolor sit amet, consectetur adipiscing elit. Curabitur dignissim orci eget risus tincidunt ultrices."

sections:
  - id: section_1
    title: "Section 1"
    fields:
      - id: question_1
        type: email
        label: What’s your email?
        placeholder: hello@declarativeforms.com
        validators:
          - required
    next: done
```

This file fully defines your form — its structure, its fields, and how it flows.

---

## 2. Push to your repository

Commit and push the file to your GitHub repository.

That’s all the setup required.

Your repository is the source of truth. Declarative Forms reads directly from it.

---

## 3. Open your form

Once the file is pushed, navigate to:

```
https://app.declarativeforms.com/<organization>/<repository>/<file-name>
```

For example:

```
https://app.declarativeforms.com/acme/forms/basic
```

(Note: the `.yaml` extension is not included in the URL.)

Your form is now live and ready to use.

---

## What Just Happened?

Declarative Forms loaded the YAML definition from your repository and rendered it as a complete form.

The structure you defined:

* Specifies the version
* Describes the form
* Defines its sections
* Defines the fields within each section
* Controls how the form progresses

There is no hidden configuration layer.
What you define in the file is exactly what gets rendered.

Because the form is declarative:

* The entire structure is visible in one place
* Changes can be version-controlled
* The definition remains portable
* The form can evolve predictably
