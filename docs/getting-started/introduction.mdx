Declarative Forms is a developer-first form system that renders hosted forms from YAML files in public GitHub repositories.

`https://app.declarativeforms.com/{owner}/{repository}/{file}`

If your file is `bug_report.yaml`, the form URL ends with `/bug_report`.

## What it is

A declarative form definition model:

- Form structure lives in a YAML file
- Sections and fields are explicit in source
- Section routing is defined with `next`
- The hosted app loads the YAML and renders the form

## What problem it solves

Form builders work well for one-off forms, but they become harder to manage when forms are part of real workflows and change over time.

Declarative Forms keeps forms in the same workflow as the rest of your work: write text, commit changes, review diffs, and ship updates from GitHub.

## Why it is different

UI-first tools hide form structure behind builder state. Declarative Forms treats the form definition as source.

That gives you:

- Git history for form changes
- Pull request review for updates
- A workflow that fits code-first and LLM-assisted development

## Core value proposition

You can go from idea to live form using the same workflow you already use to ship code.

No separate builder process. No hidden editor state.

## High-level how it works

1. Create a YAML form file with `version: 1`
2. Push the file to the `main` branch of a public GitHub repository
3. Open `https://app.declarativeforms.com/{owner}/{repository}/{file}`
4. The hosted app reads the YAML and renders the form
