## What is Declarative Forms?

Declarative Forms is a developer-first alternative to traditional form platforms. Instead of building forms through visual editors, you define forms as YAML configuration in a GitHub repository.

---

## Forms as Code

A form is a YAML file. You write what the form should contain and the platform handles the rest.

```yaml
version: 1
title: "Feedback"
description: "Help us improve our product!"

locale: "en"
measurements:
  # ...

start_date: "2026-01-01"
end_date: "2026-03-31"

completion:
    # ...

sections:
  - id: section_1
    title: "Section 1"
    fields:
      - id: question_1
        type: email
        label: What’s your email?
        placeholder: hello@declarativeforms.com
        validators:
          - required
    next: done

connections:
    # ...
```

## Why code instead of a visual editor

Visual editors are a good fit when you need to publish a few simple forms quickly. But when forms become part of a product or an operational workflow, the editing model starts to matter. If the form only lives inside a third-party editor, it becomes harder to review changes, track history, and manage it alongside the rest of your system.

Defining forms in code keeps the form close to the product it belongs to. You can version it, review it in pull requests, collaborate in GitHub, and move it with the rest of your codebase. It is not a better model for every team. It is a better model for teams that want direct control over how their forms are defined.
