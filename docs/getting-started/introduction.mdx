Declarative Forms is a form-building system where forms are declared in YAML and rendered as hosted forms.

`https://app.declarativeforms.com/{owner}/{repository}/{file}`

If your file is `rental_application.yaml`, the form URL ends with `/rental_application`.

## What it is

A declarative form definition model:

- Form structure is a YAML file
- Sections and fields are explicit in source
- Routing between sections is defined in `next`

## What problem it solves

Most product work is now code-first and Git-first. Traditional form workflows still force visual builder editing, which breaks developer momentum.

Declarative Forms keeps forms inside the same workflow as engineering work: write text, commit changes, review diffs, ship updates.

## Why it is different

UI-first form tools treat forms as builder state. Declarative Forms treats forms as source definitions.

That gives you:

- Git history for every form change
- Pull request review for form updates
- A workflow that matches LLM-assisted development

## Core value proposition

You can move from idea to live form using the same workflow you already use for code.

No parallel UI authoring flow. No hidden builder state.

## High-level how it works

1. Create a YAML form file with `version: 1`
2. Push that file to the `main` branch of a public GitHub repository
3. Open `https://app.declarativeforms.com/{owner}/{repository}/{file}`
4. The hosted app loads the YAML and renders the form
