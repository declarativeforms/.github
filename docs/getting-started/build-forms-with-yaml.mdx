title: "Build forms with YAML"
description: "Define forms in YAML, store them in GitHub, and render them at a public URL. Everything you need to get started."
---

Declarative Forms lets you define a form entirely in a YAML file. Store it in a GitHub repository, and the platform renders it as an interactive form at a public URL. There is no visual editor, no account to create, and nothing to deploy. The YAML file is the source of truth.

This page covers everything you need to build, publish, and configure forms.

## Create and publish a form

<Steps>
  <Step title="Create a YAML file">
    In the root of a **public** GitHub repository, create a `.yaml` file on the `main` branch. The filename becomes part of the URL — for example, `contact.yaml` becomes `/contact`.
  </Step>

  <Step title="Define your form">
    Use the annotated example below as a starting point. Copy the active (uncommented) YAML for a working contact form, or uncomment sections to add more features.
  </Step>

  <Step title="Commit and open">
    Commit to `main`, then open:

    ```text
    https://frms.dev/<owner>/<repo>/<filename>
    ```

    Replace `<owner>` with your GitHub username or organization, `<repo>` with the repository name, and `<filename>` with the YAML filename without the `.yaml` extension.

    Changes you commit to `main` are reflected the next time the form is loaded.
  </Step>
</Steps>

Want to see a live form before building your own? [Open this example](https://frms.dev/c979ac5b).

## Annotated example

The active YAML below is a complete, working contact form. Copy it as-is to get started. Commented-out blocks show progressively advanced alternatives — uncomment what you need.

```yaml
# ============================================================================
# FORM — top-level properties
# ============================================================================

# Required. Schema version. Use 1 for all forms.
version: 1

# Required. Displayed at the top of the rendered form.
title: "Contact us"

# Optional. Displayed below the title.
description: "Send us a message and we will get back to you."

# --- Localized alternative (uncomment to replace the plain strings above) ---
# Any text property in the schema accepts either a plain string or
# a locale map object. This applies to title, description, label,
# placeholder, message, option labels, and all connection text fields.
#
# title:
#   en: "Contact us"
#   es: "Contáctenos"
# description:
#   en: "Send us a message and we will get back to you."
#   es: "Envíenos un mensaje y nos comunicaremos con usted."

# --- Form availability (uncomment to restrict when the form can be used) ---
# ISO 8601 timestamps. If start_date is in the future → "Form Not Yet Open".
# If end_date is in the past → "Form Closed". Both are optional.
#
# start_date: "2025-06-01T00:00:00Z"
# end_date: "2025-12-31T23:59:59Z"

# --- Locale override (uncomment to force a default language) ---
# Overrides the browser language. Syncs to the ?lang= query parameter.
# If omitted, locale is detected from navigator.language, falling back to "en".
#
# locale: "es"

# --- Analytics (uncomment to enable Mixpanel tracking) ---
#
# measurements:
#   mixpanel: "your-mixpanel-project-token"


# ============================================================================
# SECTIONS — each section is one step/page in the form.
# The form renders one section at a time.
# ============================================================================

sections:

  - id: contact
    title: "Your details"

    # --- Localized section title (uncomment to replace the plain string) ---
    # title:
    #   en: "Your details"
    #   es: "Tus datos"

    fields:

      # ====================================================================
      # FIELD — shared properties
      # Every field requires `id`, `type`, and `label`.
      # Optional shared properties: placeholder, validators, visible_when.
      # ====================================================================

      # --- Simple field ---
      - id: full_name
        type: short_text
        label: "Full name"

      # --- Field with placeholder and required validator ---
      - id: email
        type: email
        label: "Email address"
        placeholder: "jane@example.com"
        validators:
          - "required"

      # --- Field with multiple validators ---
      - id: message
        type: long_text
        label: "Message"
        placeholder: "How can we help?"
        validators:
          - "required"
          - type: min_length
            value: 10
          # --- Custom error message (uncomment to override the default) ---
          #   message: "Please write at least 10 characters"
          #
          # --- Localized error message (uncomment for multi-language) ---
          #   message:
          #     en: "Please write at least 10 characters"
          #     es: "Escriba al menos 10 caracteres"
          - type: max_length
            value: 2000

      # --- Conditional visibility (uncomment to show a field only when
      #     a condition is met. Hidden fields are excluded from validation.
      #     The expression receives `data` — an object of all form values.) ---
      #
      # - id: company
      #   type: short_text
      #   label: "Company name"
      #   visible_when: "data.email !== ''"

      # --- Selection fields (uncomment to add dropdowns, radio buttons,
      #     or checkboxes. Options can be plain strings or label/value
      #     objects. String shorthand: "Engineering" becomes both the
      #     label and the stored value.) ---
      #
      # - id: department
      #   type: dropdown
      #   label: "Department"
      #   options:
      #     - "Engineering"
      #     - "Design"
      #     - label: "Marketing"
      #       value: "marketing"
      #   validators:
      #     - "required"
      #
      # --- Searchable dropdown (uncomment for long option lists) ---
      # - id: country
      #   type: dropdown
      #   label: "Country"
      #   searchable: true
      #   options:
      #     - label: "United States"
      #       value: "US"
      #     - label: "Germany"
      #       value: "DE"
      #
      # --- Radio buttons (uncomment) ---
      # - id: priority
      #   type: single_select
      #   label: "Priority"
      #   options:
      #     - label: "Low"
      #       value: "low"
      #     - label: "High"
      #       value: "high"
      #
      # --- Checkboxes with min/max selection count (uncomment) ---
      # - id: interests
      #   type: multiple_select
      #   label: "Interests (pick 1–3)"
      #   options:
      #     - label: "Technology"
      #       value: "tech"
      #     - label: "Design"
      #       value: "design"
      #     - label: "Business"
      #       value: "business"
      #   validators:
      #     - type: min
      #       value: 1
      #     - type: max
      #       value: 3
      #
      # --- Rating scale (uncomment for NPS or satisfaction scores) ---
      # min/max validators define both the button range AND validation.
      # Default range is 1–5 if not specified.
      # - id: score
      #   type: rating
      #   label: "How likely are you to recommend us?"
      #   min_label: "Not likely"
      #   max_label: "Very likely"
      #   validators:
      #     - type: min
      #       value: 0
      #     - type: max
      #       value: 10


    # ==================================================================
    # SECTION NAVIGATION — the `next` property controls what happens
    # when the user completes this section.
    # ==================================================================

    # Simple: submit the form and show the completion page.
    next: done

    # --- Navigate to another section (uncomment) ---
    # next: another_section_id

    # --- Redirect to an external URL (uncomment) ---
    # next: "https://example.com/thank-you"

    # --- Conditional navigation (uncomment to route based on answers) ---
    # Evaluated top to bottom. First matching `when` wins.
    # `else` is the fallback. Must be last.
    #
    # next:
    #   - when: "data.message.length > 100"
    #     go: detailed_followup
    #   - else: done


  # --- Additional sections (uncomment to create a multi-step form) ---
  # Each section is one page. The `next` property chains them together.
  #
  # - id: detailed_followup
  #   title: "Tell us more"
  #   fields:
  #     - id: priority
  #       type: single_select
  #       label: "How urgent is this?"
  #       options:
  #         - "Low"
  #         - "Medium"
  #         - "High"
  #       validators:
  #         - "required"
  #   next: done


# ============================================================================
# COMPLETION — custom thank-you page (optional).
# If omitted, a default thank-you screen is shown.
# All fields support Handlebars: {{data.field_id}} inserts the
# respondent's submitted value.
# ============================================================================

# --- Simple completion ---
completion:
  title: "Message received"
  message: "Thanks, we'll get back to you soon."

# --- Completion with Handlebars and a button (uncomment to replace above) ---
# completion:
#   title: "Thanks, {{data.full_name}}!"
#   message: "We received your message and will reply to {{data.email}}."
#   button:
#     label: "Back to our site"
#     url: "https://example.com"

# --- Localized completion (uncomment to replace above) ---
# completion:
#   title:
#     en: "Thanks, {{data.full_name}}!"
#     es: "¡Gracias, {{data.full_name}}!"
#   message:
#     en: "We'll reply to {{data.email}}."
#     es: "Responderemos a {{data.email}}."
#   button:
#     label:
#       en: "Back to our site"
#       es: "Volver a nuestro sitio"
#     url: "https://example.com"


# ============================================================================
# CONNECTIONS — triggered on form submission (required, can be empty array).
# Multiple connections run in parallel.
# All text fields support Handlebars.
# ============================================================================

connections:

  # --- Email: send submissions to an inbox ---
  - type: email
    to: "hello@example.com"
    subject: "New contact form submission"
    include_responses: true

  # --- Email with custom body and Handlebars (uncomment to replace above) ---
  # - type: email
  #   to: "hello@example.com"
  #   subject: "Message from {{data.full_name}}"
  #   body: |
  #     Name: {{data.full_name}}
  #     Email: {{data.email}}
  #     Message: {{data.message}}
  #   include_responses: false

  # --- Email to the respondent (uncomment to add a confirmation email) ---
  # - type: email
  #   to: "{{data.email}}"
  #   subject: "We received your message"
  #   body: |
  #     Hi {{data.full_name}},
  #
  #     Thanks for reaching out. We'll be in touch shortly.

  # --- Localized email (uncomment for multi-language) ---
  # - type: email
  #   to: "hello@example.com"
  #   subject:
  #     en: "New message from {{data.full_name}}"
  #     es: "Nuevo mensaje de {{data.full_name}}"
  #   include_responses: true

  # --- Webhook: POST submission data as JSON (uncomment) ---
  # Payload includes: id, form_id, data, metadata, status, timestamps.
  # - type: webhook
  #   url: "https://api.example.com/webhooks/form-submitted"

  # --- Airtable: write to an Airtable base (uncomment) ---
  # Requires an OAuth connection set up via /connections.
  # - type: airtable
  #   connection_id: "conn_abc123"
  #   base_id: "appXXXXXXXXXXXXXX"
  #   table_id_or_name: "Form Responses"


# ============================================================================
# VALIDATORS — quick reference of all seven types.
# Defined per field in the `validators` array.
# ============================================================================
#
# validators:
#
#   # 1. Required — prevents empty submission
#   - "required"
#
#   # 2. Pattern — regex match
#   - type: pattern
#     regex: "^[A-Z]"
#     message: "Must start with a capital letter"    # optional
#
#   # 3. Min value — numeric comparison (number), date comparison (date),
#   #    file count (file_upload), selection count (multiple_select)
#   - type: min
#     value: 1
#
#   # 4. Max value — same context-dependent behavior as min
#   - type: max
#     value: 100
#
#   # 5. Min length — string character count
#   - type: min_length
#     value: 3
#
#   # 6. Max length — string character count
#   - type: max_length
#     value: 500
#
#   # 7. Expression — JavaScript expression with access to all form data.
#   #    Fails closed: if the expression throws, validation fails.
#   - type: expression
#     expression: "data.password === data.confirm_password"
#     message: "Passwords must match"                # required for expression


# ============================================================================
# FIELD TYPES — quick reference of all supported types.
# Set via the `type` property on each field.
# ============================================================================
#
# Text & Input:
#   short_text    — single-line text input
#   long_text     — multi-line text area
#   email         — email with optional OTP (otp: true) and free email
#                   blocking (block_free_email: true)
#   number        — numeric input (whole integers by default)
#   date          — native date picker (min/max as ISO date strings)
#   url           — URL input
#   mobile_number — phone number input
#
# Selection:
#   dropdown        — select menu (searchable: true for combobox mode)
#   single_select   — radio buttons
#   multiple_select — checkboxes (min/max control selection count)
#   rating          — numbered button row (min/max define the range;
#                     default 1–5; supports min_label / max_label)
#
# Location & Address (powered by Google Places):
#   address          — full address autocomplete
#   address_locality — city/locality autocomplete
#   address_region   — state/region autocomplete
#   address_country  — country autocomplete
#   geolocation      — GPS coordinates via browser Geolocation API
#
# Media & Capture:
#   file_upload — drag-and-drop file upload (min/max control file count)
#   camera      — device camera capture (facing_mode: "front" | "rear")
#   signature   — canvas drawing pad
#
# Utility:
#   hidden    — invisible field (pre-populate via URL: ?field_id=value)
#   turnstile — Cloudflare CAPTCHA (always required, auto-injected)
```
